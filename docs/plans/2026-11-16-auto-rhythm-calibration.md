# 自动鼓点对齐与可视化校准实施方案

## 目标

节拍器固定每响一步，用户只设置目标步频。日常界面自动识别音乐节奏与起拍，移除原拍／双拍等选择及手动 BPM 主操作。提供独立可视化校准页、真实音频节点匹配参考与用户确认，同时支持曲库素材删除。

## 实现

- 沿用实际 PCM 的自动节奏与强拍起点分析，保留试听和导出的统一采样时间线。历史手动 BPM 可以重新自动识别。适配计算由程序选择合适节奏关系，用户只操作“适配当前步频”。
- 新增有界音频片段分析，返回实际采样包络、鼓点时间、强拍权重和分析可靠度。匹配参考依据节点到当前节拍网格的时间误差计算，证据不足时显示无法可靠评分。
- 新增 #/track/{entryId}/align。左右显示节拍器与 BGM 的同步纹波、节点与同一播放游标。用户可选择片段、试听、微调起拍、应用自动参考、确认或取消。微调立即用于试听，确认后保存该编排实例，取消恢复已保存值。
- 曲库删除使用明确确认界面。删除原始素材时包含依赖其的适配版本，显示所有影响。正在分析、制作或导出使用的素材通过实际使用保护保持一致，用户收到具体状态提示。删除成功后同步当前编排和曲库，保留已完成导出。
- 保留既有项目格式、重复素材实例隔离、主题、播放和后台任务生命周期。辅助字号至少14px，主要交互至少44px，桌面左右双栏、手机上下排列。

## 文件与分工

1. 后端音频代理负责新增 rhythm.py 与针对真实合成 PCM 的回归，返回包络和节点数据，根代理接 API。
2. 删除代理负责 storage.py、jobs.py、app.py 的删除及并发保护和相关测试，与根代理协调 API 编辑。
3. 前端代理负责 TrackTempo.tsx 简化、BeatAlignment.tsx、rhythm.ts 辅助计算及独立样式和相关测试。
4. 根代理负责 api.ts、App.tsx、routing.ts、project.ts 集成、真实浏览器验证、文档及发布。

## 验证

真实非零起拍、半拍偏移、弱节奏、短音频、变速版和历史素材均需覆盖。匹配度随有意义的偏移下降，纯音和静音显示证据不足。确认／取消、切页、跳转、重复实例、曲库删除依赖与活动导出保护须从正常入口验证。最后运行完整前后端测试和生产构建，在深浅主题与390px手机布局中验收，再更新本地服务和 GitHub。

## 实际验收

- 后端111项测试、前端40项测试通过，TypeScript和Vite生产构建通过。
- 真实Chromium验证旧手动BPM重新自动提取、第二首91ms鼓点对齐、当前片段真实节点、偏移后参考匹配度下降、音乐连续播放、取消还原与确认保存。
- 独立子路由刷新、跨片段读取、两套主题和390px布局通过，主要辅助文字至少14px。
- 真实WAV下载、删除确认和取消、原素材及关联变速版删除、编排同步、已完成导出继续下载通过。
- 弱节奏纯音无伪造节点和匹配分数。文件占用导致的延迟磁盘清理会在重新打开素材库时重试，并有回归覆盖。
